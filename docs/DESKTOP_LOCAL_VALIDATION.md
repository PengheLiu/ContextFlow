# 桌面端：本地完整验证指南（macOS）

适用对象：需要验证安装包或联调源码的维护者。首次接触产品的普通用户仍按「Chrome 扩展 → 官网桌面下载 → 安装打开 → 回扩展连接」开始；本指南不替代该主流程。

目标：从安装匹配渠道的桌面包开始，走完浏览器连接、批注、模型 / Agent、笔记同步、退出重连与数据保护。建议先完成第一轮，再做可选的异常测试。

这是开发者本机验收指南，不是正式发布承诺。当前完整流程要求 **1.1.0 或更高版本的匹配扩展**，内置运行时要求 macOS 13.5 或更高；每个安装包的签名、公证与公开状态以[下载页](https://pengheliu.github.io/ContextFlow/download.html)和[发布清单](./RELEASE_READINESS.md)为准。Windows 需要在 Windows 实机另行验收，Mac 上通过不代表 Windows 通过。版本号相同也可能是不同渠道或代码快照，请记录来源与校验摘要。

## 先选择一种验收路径，不交叉混用

| 路径 | 桌面安装包 | 扩展身份 | 适用范围 |
| --- | --- | --- | --- |
| A：公开产品验收 | 官网独立分发 `direct` 包或正式 `release` 包 | 商店 ID `aemncphfnlpbhlddifhohpgegejjejfm`，且具备「连接桌面端」入口 | 普通用户的安装、原生授权与覆盖升级 |
| B：源码开发联调 | 明确按下文构建的 `preview` 包 | 固定开发 ID `cgimipjfmopjcaedmgccaodjppdpkfjf` | 当前源码的功能与界面验证，不冒充公开发行验收 |

**公开产品包只接受商店 ID，不能与固定开发 ID 配对。** `preview` 包才额外接受开发 ID。不要为了让测试通过修改正式 allowlist、把开发扩展的 ID 伪装成商店身份，或把开发联调结果当成商店更新已上线。若公开商店暂未提供匹配入口，路径 A 的原生连接验收暂不能完成；可以继续基础阅读，或明确改用路径 B，不能宣称路径 A 已通过。

## 0. 开始前：保护现有数据

1. 停止旧的终端 / 常驻服务，确认 `127.0.0.1:7317` 没有监听进程。旧的登录自启也应暂停，避免下次登录启动两套服务。不要直接强杀所有 Node 进程。
2. **首次打开桌面端之前**，备份原有服务数据目录。默认是当前用户的 `.contextflow`，自定义过 `CONTEXTFLOW_DIR` 的则备份实际目录。应在服务停止后复制整个目录，而非运行时只复制 SQLite 主文件。
3. 在有历史记录的 Chrome 扩展中，打开「我的阅读库」→「备份与恢复」→「下载完整备份」，确认 JSON 已下载。它与服务数据备份是两份不同的备份。
4. 不卸载原扩展、不清除浏览器数据、不删除 `.contextflow`。需要避免新旧扩展同时工作时，只临时停用旧扩展。

注意：桌面端写入配置时会加密 API key、思源 token 和 Agent 环境配置；旧配置缺少必要字段时，首次启动也可能补写。因此不要认为“不点保存就一定能直接切回旧 CLI”。后续优先通过桌面端管理服务；回退旧 CLI 必须保留并使用测试前备份，不能只重启旧服务。

完整阅读备份包含有效阅读记录、历史回答和引用图片，不包含模型密钥、原网页全文或仅存在于服务端的记录。JSON 和服务数据库不是加密备份，请保存在私人目录，不要上传 GitHub。

## 1. 安装并打开桌面端

使用与机器架构及上述路径匹配的 DMG：

- **路径 A：** 从官网下载，并核对对应 SHA-256、签名说明与系统要求。冻结的 `release/desktop/candidate-1-1-0/ContextFlow-1.1.0-mac-arm64.dmg` 是 `direct` 包，只接受商店 ID，不接受下文的固定开发 ID。目录名中的 candidate 不是开发扩展兼容性的证明，也不代表 Developer ID 签名或 Apple 公证。
- **路径 B：** 先保护数据、退出已安装应用，再从源码根目录执行以下构建。默认 `desktop:prepare` 生成 `preview` 资源；这里不要加 `--direct` 或 `--release`。产物另存，不覆盖任何已公开或冻结的同版本文件。

```sh
npm ci
npm run desktop:install
npm run desktop:prepare
npm --prefix desktop run dist -- --mac --arm64 --target dmg --artifact-subdir local-validation
node tools/check-desktop-package.mjs
npm run build:ext
```

路径 B 的新 DMG 位于 `release/desktop/local-validation/`。旧 `menu-bar-preview/`、`onboarding-preview/`、`system-integration-preview/`、`product-preview/` 中的历史包不能替代本次构建。各目标实际产物和验证状态见[发布清单](./RELEASE_READINESS.md)。先从菜单栏或应用菜单退出已安装版本，再覆盖安装，不删除应用数据。两种路径均从「应用程序」打开安装副本，不直接运行源码中的 `.app` 暂存产物。

1. 双击 DMG，将 `ContextFlow.app` 拖到「应用程序」。如果已有同名应用，先退出旧版并核对是否需要保留，不要覆盖正在运行的应用。
2. 推出 DMG，从「应用程序」打开 ContextFlow。不要一直从挂载的 DMG 或构建临时目录运行：浏览器桥接会记录应用的实际位置。
3. 如果只提示开发者无法验证，且确认这是自己刚构建、未遭修改的包，可在尝试打开后，到「系统设置」→「隐私与安全性」按系统提供的「仍要打开」确认。参见 [Apple 官方说明](https://support.apple.com/zh-cn/102445)。
4. 如果提示“已损坏”“将损坏你的电脑”，或没有可用的确认入口，先停止并记录提示，不能统一按“未签名”处理。不要关闭 Gatekeeper、批量移除隔离标记或修改系统安全策略。

预期结果：

- 先出现「首次准备」，日常导航为「首页 / AI 助手 / 笔记 / 设置与帮助」。首次准备可返回、跳过，稍后从保存的步骤继续。
- 窗口先出现，本地连接与工具发现随后准备；侧栏显示「本地连接正常」。模型可以尚未验证、浏览器可以尚未授权，不能全绿假报完成。
- 「设置与帮助」的「浏览器授权」中显示桥接已注册；「AI 助手 / 笔记」能看到自动发现结果。未发现可选软件属于正常空状态，提供手动选择。
- 不要求安装 Node、运行 npm 或保持终端打开。

如果显示「检测到旧服务」，说明还有服务占用端口。先核对归属，不要点击其他项目的停止按钮或强杀端口进程。本指南开始前已停掉旧服务的本机，不应再出现该状态。

**不要用 `npm run desktop:dev` 代替本轮安装验证。** 开发运行不会修改系统的浏览器注册，不能用于验证完整 Native Messaging 配对。

## 2. 准备与桌面渠道匹配的扩展

桌面桥接需要 `nativeMessaging` 权限，以及实际存在的「连接桌面端」入口。版本号和扩展 ID 都要匹配，只有源码里实现了功能不代表商店已经发布。

**路径 A：公开产品验收**

1. 从商店安装或更新同一条目，在 `chrome://extensions` 核对 ID 为 `aemncphfnlpbhlddifhohpgegejjejfm`、版本满足 1.1.0+，并按 Chrome 提示核对新增权限。
2. 打开「扩展程序选项」→「连接与设置」，确认有「连接桌面端」入口。没有入口时停止本轮原生连接验收，保留数据，不卸载、清空或改用开发 ID 绕过。
3. 只启用这份商店扩展，临时停用可能重复注入的开发扩展；安装或更新前已打开的文章需要刷新。

**路径 B：源码开发联调**

1. 在 Chrome 地址栏输入 `chrome://extensions`，开启右上角「开发者模式」。
2. 如果已加载相同开发版，点击其「重新加载」，不要移除再安装。
3. 如果尚未加载，点击「加载已解压的扩展程序」，选择源码目录里的 **`extension/dist`**，不是源码根目录、`extension` 或商店 ZIP。
4. 核对版本与本次源码一致，固定开发 ID 为 `cgimipjfmopjcaedmgccaodjppdpkfjf`。桌面端必须是本次的 `preview` 包；版本号相同也不保证代码或渠道相同，必须重载当前构建目录。
5. 若商店版也启用，临时停用商店版，避免双工具条；不要卸载。商店版 ID 为 `aemncphfnlpbhlddifhohpgegejjejfm`。
6. 固定开发扩展到 Chrome 工具栏。安装 / 重载之前已打开的文章，稍后刷新一次。

两种扩展 ID、不同 Chrome 用户配置的本地阅读库相互独立；开发版里没有商店版旧记录，不等于数据丢失。需要复制记录时，用阅读库备份的「选择备份文件」预览，再「确认补充记录」。恢复只补充缺失记录，不覆盖已有记录，也不会自动调用 AI 或写笔记软件。

## 3. 连接浏览器与桌面端

1. 保持 ContextFlow 桌面端打开。
2. 在扩展管理页打开上述所选路径的匹配扩展「扩展程序选项」，进入「连接与设置」。
3. 在「使用 ContextFlow 桌面端连接」里阅读说明，勾选同意项，再点击「连接桌面端」。**本轮不要运行下面的旧服务包安装命令，也不需要手动生成配对码。**
4. 桌面端会弹出连接申请，核对来源和安装编号是自己刚操作的匹配扩展，再点「允许连接」。不要批准不认识的申请。
5. 返回 Chrome，检查连接状态；桌面端「设置与帮助」的「浏览器授权」中应出现对应安装实例。首次准备的连接步骤可继续。

预期结果：扩展显示本地服务已连接，桌面端出现一条对应浏览器连接。已有其他授权时，总数不一定恰好为 1。**连接成功不等于模型、Agent 或笔记同步已测试成功。**

## 4. 先验证不依赖 AI 的阅读闭环

打开扩展欢迎页的「打开练习文章」，或访问 [练习文章](https://pengheliu.github.io/ContextFlow/demo.html)。使用普通 HTML 网页，不用 Chrome 内部页、扩展商店、内置 PDF 阅读器或本地文件。

1. 选中一句原文，点击「批注」，输入 `桌面版验证：第一条批注`。
2. 点击面板外关闭，再从原文或侧栏打开这条记录，核对文字仍在。
3. 在侧栏修改为 `桌面版验证：修改后仍同步`，再从原文打开，核对两处一致。不要同时编辑同一条记录。
4. 截取一张不含隐私的小图，复制后将光标放入批注输入区域，粘贴；核对出现图片且保存完成。复制截图的图片数据，不是只复制图片网址。
5. 刷新文章，检查批注、引用和图片仍在。
6. 点击侧栏底部「下载」，确认生成 Markdown；在扩展「我的阅读库」里搜索刚才的文字，核对文章和记录可找到。

预期结果：就地面板和侧栏显示同一条记录；刷新不丢失；图片保存失败时有反馈，不假装已导出完整文件。

## 5. 配置并验证 LLM

1. 桌面端进入「AI 助手」→「AI 模型与翻译」，确认接口类型、Base URL、API key、模型及目标语言。已有配置会复用；密钥字段留空表示不改，不要求重新填明文。自动发现的 Agent 只是候选，不会替你切换回答方式。
2. 点击「获取模型」。成功时应明确提示获取到多少个模型；失败时应给出错误。提供商不支持列举模型时，可以手动填写有效模型名。
3. 点击「测试模型连接」。它发送固定短消息，可能产生少量模型费用，不发送文章或笔记，**也不保存草稿**。
4. 测试成功后点击「保存更改」。仅获取模型或测试通过，不等于配置已保存。
5. 去文章侧栏的「配置」或扩展选项页查看同一模型状态。必要时关闭设置再打开；已保存且匹配的测试记录应能看到，不应无故回到「尚未测试」。修改模型、地址或密钥后要求重新测试是合理行为。
6. 在「解释回答方式」选择 `LLM` 并保存；选中一段新的原文点「解释」，提问「用两句话解释这段内容」。
7. 有答案后修改顶部问题，再点顶部提交按钮或按 Enter，检查确实发起新请求；不应要求滚到长答案底部才能重新解释。正在处理时不要重复提交。
8. 再测试一次翻译和速览。它们使用模型能力，不代表本地 Agent 同时可用。

预期结果：获取模型有数量反馈；测试和保存含义清楚；新答案正常显示并保留；错误不以原始 JSON 假装正常答案。

如需检查公式，可让模型「用 Brier loss 举例，包含行内公式、独立公式和一个表格」。检查弹窗、侧栏和阅读库的显示一致。支持 `$…$`、`$$…$$`、`\(…\)`、`\[…\]`、math 围栏及常见 GFM 格式；不是所有 Markdown 插件都支持。Mermaid / 任意 HTML 不执行，远程图片不会自动加载，详见 [Markdown 兼容范围](MARKDOWN.md)。导出保留原始 Markdown，不导出渲染后的 HTML。

## 6. 配置并验证 Agent（可选）

1. 在同一设置页选择「本地 Agent」，点击「检测安装」。第三方 Agent 需自行安装并完成登录，ContextFlow 安装器不会自动替你安装或登录所有 Agent。
2. 选择已检测到的 Agent；区分「程序安装」与「实际回答」两个状态。
3. 点击「测试 Agent 连接」，验证登录与真实模型响应；通过后保存。该测试不读取文章或笔记，也不证明目录读取已经验证。
4. 如果使用自定义程序，点桌面端「选择 Agent 程序」后，确认类型与完整路径，直接测试当前草稿，通过后再保存；不能填写终端别名。测试不会保存配置或授予笔记权限。改变程序、路径或权限档后需重测，不能复用原绿灯。
5. 先使用支持安全档的 Agent，保持「安全」权限。测试若提示该 Agent 不支持安全档，先换支持的 Agent，不要仅为通过测试启用完整权限。
6. 想验证读笔记时，创建专用测试笔记目录，在里面放一条不含隐私的标记内容。用「允许读取的笔记库」旁的「选择只读笔记目录」选中它，保存，再从文章发起要求检索该标记的问题。选中笔记写入目的地不自动授予 Agent 读取权限。
7. 到阅读页设置检查 Agent 测试状态是否与桌面端一致；切换 Agent 后不得显示上一个 Agent 的成功状态。

Codex 使用多配置目录时，在「Codex 配置目录」选择与实际终端一致的位置（桌面端可选文件夹，浏览器可填写路径）。先测试草稿，通过后再保存；修改目录必须使旧测试结果失效。留空退回界面显示的默认目录，不自动复制账号凭据，也不授予笔记权限。旧服务不支持该字段时应提示更新，不向旧接口发送不认识的字段。模型不存在、推理档不支持、限流、认证失败或空回答应有不同反馈，不能一律提示“终端登录”。

预期结果：已安装不冒充已登录；连接失败可重试；笔记读取只在授权范围内执行。LLM 快速回答与 Agent 工具辅助的能力差异可从「解释回答方式」旁的问号查看。

## 7. 验证写入笔记软件

第一轮推荐单独创建一个空的 `ContextFlow-验证笔记` 文件夹，不要直接指向正在工作的正式笔记库。

1. 在「笔记」的「笔记同步」选择 `Markdown`。自动发现的 Obsidian 库可点选填入，但不会自动保存或授权。
2. 点对应字段旁的「选择文件夹」，选择刚创建的文件夹，再点「保存更改」。**目录选择只填表，不立即保存。** 核对显示的最终位置，再点「确认使用这个位置」；此时应是「位置已确认 · 待同步」，不是「已验证写入」。
3. 回到测试文章，在侧栏主动点击「同步」。自动保存阅读记录，不等于自动写入笔记软件。
4. 打开生成的 Markdown，核对文章来源、批注、问题、回答和图片；文章有对应内容时，区块顺序应为「速览 → 批注 → 解释 → 翻译」，子条目按列点组织。不存在的内容可省略。
5. 修改一条批注，再同步一次：应更新同一篇文章的笔记，而不是无故新增重复笔记。
6. 可选测试 Obsidian：选择 `Obsidian`，在发现结果或字段旁选择测试 Vault，保存并确认后同步。思源则需配置并单独验证思源连接，不要由 Markdown 成功推断思源成功。

预期结果：文件真实存在、内容与界面一致；重复同步不制造重复文章；同步失败有原因。产生实际文件或文档写入后，桌面首页才能显示「已验证写入」；首次仅执行无变化同步不应产生新验证凭据。其他页面改了目的地后，旧确认和验证不能套到新位置；确认时如位置已变，需重新核对。

## 8. 退出、重连和离线体验

1. Mac 右上角应出现 ContextFlow 的箭头图标，并保留 Dock 图标。点击菜单栏图标，应只展开状态菜单，不额外弹出主窗口；菜单中有服务状态、运行/排队任务数、「打开 ContextFlow」「设置与帮助」和「退出 ContextFlow」。关闭桌面窗口后，窗口隐藏、Dock 保留，AI / 同步仍可用。通过菜单栏「打开 ContextFlow」或 Dock 重新显示同一个窗口。刘海屏应检查图标确实位于可点击区域；程序自动检查屏幕几何，但无法替代肉眼确认或绕过第三方隐藏工具。Windows 托盘无法创建时应保留最小化窗口。均不能让所有入口同时消失。
2. 等待任务结束后，从菜单栏选「退出 ContextFlow」：此时服务才应停止。可在终端用 `lsof -nP -iTCP:7317 -sTCP:LISTEN` 检查；无输出表示没有监听。
3. 桌面端退出后，在文章里新增一条批注，检查本地保存、阅读库和 Markdown 下载仍可用；新的 AI 请求 / 笔记同步应明确提示连接问题，不能无响应。已有 AI 缓存答案仍显示不代表服务还在运行。
4. 从「应用程序」重新打开桌面端，再回文章检查连接或重新打开侧栏；必要时刷新文章。原配对应保留，不需要重装或重新生成配对码。对刚才的离线批注主动同步，检查落盘。
5. 可选在「设置与帮助」开启「登录后自动启动」，按系统提示检查登录项。重启电脑前保存其他工作；登录后应只有桌面端管理的一份服务。旧 LaunchAgent 继续保持暂停。
6. 连续快速关闭 / 打开窗口并再次双击应用：应只保留一个窗口、一份服务，恢复已存在的窗口。若不同构建还在运行，必须明确提示先退出旧版，不能把唤起旧进程伪装成新版已启动。
7. 在网页完成新的实际回答和一次同步后，桌面末步状态应自动更新，不靠手动刷新。真实写入可确认同一目的地；无改动同步显示「同步完成 · 无新改动」，不冒充新写入。缓存回答不验证新的 AI 配置。测试通过并保存后「继续」应及时可用；测试、保存进行中或有未保存改动时应显示明确原因。

首次从旧预览升级后，Agent 测试结果新增了权限档绑定，旧格式不自动视为当前配置已验证。请主动重测一次；它不会保存草稿或读取笔记，实际测试仍使用无工具的受限会话。今后相同配置可跨页面恢复结果，修改程序、版本、路径、权限档或凭据后则需重测。

## 9. 可选深入验收

以下操作会改变连接或恢复配置，基础闭环通过后再做。只使用测试数据，不运行会写入真实笔记库的实验。

- **排队：** 在已有较慢 Agent 任务时提交另一条任务，观察排队状态和计时。文字可以更新，但不应整块反复消失、闪烁或抢走输入焦点。不要为了制造队列批量调用付费模型。
- **撤销与重新连接：** 先完成同步并备份，在「设置与帮助」的「浏览器授权」只撤销本次测试的安装实例。新的 AI / 同步请求应失去权限，已有本地记录保留。再在该扩展里连接并批准，权限恢复；其他浏览器授权不受影响。
- **配置草稿：** 修改一项设置但不保存，等待至少 10 秒并切回窗口，草稿不应被状态刷新覆盖。不要把未保存草稿当成已经共享给其他页面。
- **正常恢复点：** 本地服务健康且无运行或排队任务时，点「设置与帮助」→「创建恢复点」。服务短暂停止后重启，列表出现时间。恢复点包含数据库及必要 WAL、附件、配置和受系统保护的密钥；正常恢复点不保存可由 SQLite 重建的 SHM。确需测试恢复时，先再导出浏览器备份，使用不含真实改动的测试场景，再点对应「恢复」并确认。
- **故障时恢复：** 配置损坏或系统密钥不可用时，原文件应保留而不是改成默认值；不能新建正常恢复点，但可以选择已有有效恢复点。先校验文件清单、哈希与同一系统账号的解密能力，停止自己的服务并获得数据目录独占锁后才恢复。历史无锁 CLI 无法仅靠此锁可靠检测，先正常退出旧 CLI / LaunchAgent，不强杀未知进程。不要在真实配置中主动制造损坏来测试；这类反例应使用隔离数据与测试程序。
- **故障保护副本：** 恢复前单独保留原始字节，包括可能损坏的配置、WAL / SHM 及原文件缺失状态。新内容启动验证失败时精确回滚原状；它不是正常恢复点，不自动导入。通过「设置与帮助 → 查看故障保护副本」查看本机目录。副本可能含未加密的原始内容或凭据，不公开上传，也不把它当作可跨电脑使用的备份。
- **恢复边界：** 不覆盖外部 Markdown / Vault 文件、浏览器离线记录、浏览器授权或连接测试记录。浏览器记录不会随服务快照倒退，不应用它来测试“删除所有新记录”。仅适用于本电脑原系统账号。旧格式恢复点仍需校验；若其当时漏收必要 WAL，新版本不能追溯补回缺失内容。
- **诊断：** 点击「导出脱敏诊断」，打开导出的报告查看字段。应只有版本、状态、能力、计数等，不包含文章、网址、密钥或路径。原始日志不等于脱敏报告，不要直接公开。
- **更新：** 点击「前往官网下载更新」，应仅打开官网而不停止服务；首发不执行应用内自动安装。正式覆盖安装验收需使用可信签名包、正常退出旧版、确认数据保留，不能把打开下载页算成签名升级通过。

## 10. 常见卡点

| 现象 | 先检查什么 |
| --- | --- |
| 开发扩展加载失败 / 文件不是 UTF-8 | 确认选的是本次构建的 `extension/dist`，记录 Chrome 的完整错误。不要改编码后假装构建通过，也不要移除有记录的扩展。 |
| 找不到桌面应用 / Native host | 确认从「应用程序」启动打包 app，且桥接已注册；`direct/release` 只接受商店 ID，开发 ID 需配 `preview` 包。不要用 `desktop:dev` 代替原生注册验收。应用移动后重新打开以注册新位置，再重试。 |
| 点连接后等待 | 查看桌面端是否有待处理的批准弹窗；一次只发起一个申请。取消后可重新连接。 |
| 服务已连接，模型仍未测试 | 桥接授权与模型测试独立。确认保存的是当前模型配置，且已经实际点击测试。 |
| 旧 API key 输入框为空 | 空白占位通常表示已配置、留空不改，不代表密钥丢失；不要把占位文字复制成新密钥。 |
| Agent 显示已安装，但回答失败 | 单独测试登录和真实响应；检查所选程序与账号，不能把安装检测当作联通测试。 |
| 网页没有工具条 | 刷新安装前打开的文章，确认只启用一份测试扩展、网页类型支持及网站访问权限。 |
| 同步提示成功但找不到文件 | 检查当前选中的后端、保存的目录和同步反馈里的位置；首页的「位置已确认」不是同步结果，只有实际写入凭据才显示「已验证写入」。 |
| 关闭窗口后端口还在 | 正常；窗口关闭是隐藏。请从菜单栏「退出 ContextFlow」。 |
| 切回旧终端服务读不了配置 | 可能已使用桌面密钥加密；不要清空配置或强行重配，使用测试前备份制定回退步骤。 |

## 11. 结束与回退

如果继续体验：保留桌面端作为唯一服务管理入口，旧启动项继续暂停。不要同时执行 `npm run server` 或旧 `npm run service -- restart`。

如果暂时不继续：完成同步 / 备份，关闭桌面端的登录启动，再从菜单栏退出。采用路径 B 时暂时停用开发扩展，重新启用原商店版即可回到原浏览器界面；两者阅读数据独立。这**不代表旧服务已恢复可用**。

需要恢复旧服务时：先确认桌面端完全退出，保留本轮新增数据的另一份备份，比较当前配置是否已加密，再决定恢复测试前配置还是整套服务快照。最后才恢复旧 LaunchAgent 并启动。不能直接用旧备份覆盖测试期间新增的真实记录，也不要删除系统保护的密钥文件。首次回退建议由维护者协助完成。
