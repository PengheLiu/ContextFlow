# 版本更新

从 1.1.3 起，插件与客户端会检查官方公开版本，发现新版本后显示更新图标。现有旧版本需要先手动更新一次，才能使用这些入口。两端分别发布，版本号不必同时改变；设置页显示的是本渠道已公开的版本。

## Chrome 插件

阅读面板右上角出现向上箭头时，点击可查看当前版本、可用版本与最近检查时间。「连接与设置」中的「应用更新」也可手动检查。

Chrome 商店负责分发和安装插件更新。需要立即检查时，先保存所有阅读页的内容，再打开扩展管理，开启「开发者模式」后点击「更新」。安装更新后刷新旧文章页。不要移除扩展，移除会清除阅读库。

更新提示不会自动刷新文章或重载扩展。如果旧页面保存时提示连接已断开，先复制批注或下载文字草稿，再刷新恢复。文字草稿不包含图片，请另外保留图片；备份不表示已保存到阅读库。开发模式加载的副本需要使用新构建并重新加载，商店不会替换它。

## 桌面客户端

客户端左下角和菜单栏菜单会显示可用更新。点击后在「设置与帮助 → 应用更新」查看版本和检查结果，再前往官网下载适合系统、芯片的安装包。完成或取消运行中的任务，保留未保存内容，从应用菜单退出旧版后覆盖安装；配置、阅读数据和浏览器授权保留。

当前采用手动安装，不在后台下载、覆盖应用或重启服务。没有对应平台的已发布安装包时，不会提示安装其他架构。检查失败会保留上一次结果，并明确提示重试，不会把失败显示成已是最新版。

## 发布维护

两端仅请求 `https://pengheliu.github.io/ContextFlow/updates.json`，每 6 小时最多自动检查一次，也可手动检查。请求不附带文章、笔记、密钥或设备标识；官网托管仍会接收正常网络访问所需的信息。Chrome 自身的商店检查只在用户手动检查时触发，周期任务仅检查公开版本清单。

清单从 `product/release.json` 中的 `publishedExtension` 和已公开桌面平台生成，不使用 `candidateVersion` 冒充公开版本。先完成实际发布与核查，再更新渠道记录并执行：

```bash
npm run updates:sync
npm run updates:check
npm run test:product
npm run deploy:website -- --publish
```

官网暂存、网站 ZIP 和 Pages 部署使用同一文件白名单；部署前会拒绝与已发布记录不一致的清单。缓存和网络清单都校验版本、平台和固定目标网址，不接受任意下载地址或远程脚本。
