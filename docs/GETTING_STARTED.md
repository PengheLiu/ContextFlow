# 从第一条批注开始

[产品官网](https://pengheliu.github.io/ContextFlow/) · [桌面端下载与状态](https://pengheliu.github.io/ContextFlow/download.html) · [GitHub 首页](../README.md) · [Chrome 商店安装](https://chromewebstore.google.com/detail/contextflow/aemncphfnlpbhlddifhohpgegejjejfm) · [练习文章](https://pengheliu.github.io/ContextFlow/demo.html)

先安装 Chrome 扩展，完成「选中原文 → 写批注 → 下载 Markdown」。需要 AI 或笔记同步时，再从官网下载桌面端，回扩展确认连接。

## 安装扩展

1. 在商店点击「添加至 Chrome」，确认安装，无需开启开发者模式。
2. 点击 Chrome 右上角拼图图标，把 ContextFlow 固定到工具栏。
3. 刷新一篇普通文章。安装前已经打开的网页必须刷新。

高亮、批注、图片补充和 Markdown 导出不需要账号、桌面端、Node.js、API key 或本地服务。只想批注时，可以直接到文章选中文字，稍后再进行连接设置。

## 完成第一条批注

1. 打开[练习文章](https://pengheliu.github.io/ContextFlow/demo.html)，选中第一段的一句话。
2. 点击选区工具条「批注」，在原文旁写一句自己的理解，也可以粘贴图片。
3. 展开页面右侧把手，确认批注与原文出现在侧栏。
4. 刷新页面检查记录恢复；点击侧栏底部「下载」，用文本编辑器或 Obsidian 打开 Markdown。

**完成标志：** 刷新后记录仍在，Markdown 同时包含原文、自己的想法和来源链接。原文网页改版可能影响标记定位，但已有记录仍可导出。

## 阅读库与完整备份

更新扩展后刷新已打开的文章；如 Chrome 因新权限暂停扩展，先核对权限说明，再按 Chrome 提示决定是否启用，不通过卸载更新。

- **找回过去的记录：** 侧栏顶部的「我的阅读库」，或扩展选项页顶部的同名入口。可以按标题、网址、原文、问题、笔记搜索全部已保存在此扩展内的文章，按内容类型筛选并预览；不需要本地服务。
- **带走单篇记录：** 在阅读库选中文章，点击「下载 Markdown」，文件包含该文章的阅读记录及本地可用图片。
- **完整阅读备份：** 点击「下载完整备份」。会先等待打开的阅读页面保存编辑，再校验记录与图片；请确认浏览器下载完成，妥善保存 JSON 文件。备份可读且未加密，不包含密钥或配对码。
- **换浏览器或重新安装：** 在阅读库选择 JSON 备份，核对文章、记录、图片与预计新增数量，再点击「确认补充记录」。取消和校验失败不会写入数据；已有记录与已删除记录不会被旧备份覆盖。恢复不重启 AI 任务，刷新原文章后可查看。

范围：完整阅读备份包含此扩展内已保存的有效记录、历史回答与引用图片，不包含已删除内容、原网页全文、配置或只存在于本地服务的记录。单个 JSON 备份上限 32 MB；超限会明确提示而不是截断。恢复后的记录按原有规则保存到已连接的本地服务；写入笔记软件仍需主动点击同步。商店版与开发版的浏览器存储彼此独立，可通过兼容版本的阅读备份迁移。

## 开启 AI 和笔记同步

### 1. 从官网选择 Mac Apple Silicon 安装包

打开 [ContextFlow 桌面端下载页](https://pengheliu.github.io/ContextFlow/download.html)。当前提供 **macOS Apple Silicon（M 系列芯片）1.1.0 DMG** 与对应 SHA-256 校验文件，要求 macOS 13.5+。先在「关于本机」核对芯片，不凭浏览器名称猜测；Mac Intel 和 Windows 尚未开放安装包，不使用其他架构代替。

桌面一键连接需要 **ContextFlow Chrome 扩展 1.1.0 或更高版本**。下载前请在扩展「连接与设置」确认有「连接桌面端」入口；商店可安装版本以实际页面为准。没有入口时，可先继续高亮、批注与 Markdown 导出，不要卸载扩展。

当前 Mac 包**没有 Developer ID 签名，也未经过 Apple 公证**。SHA-256 用于核对文件字节，不代表 Apple 已验证它。遇到系统拦截时，核对官方来源并阅读 [Apple 安全说明](https://support.apple.com/zh-cn/102445)，不要关闭 Gatekeeper 或执行批量移除隔离标记的命令。若提示「已损坏」或「将损坏电脑」，停止并反馈，不一律当作普通未签名提示。

`contextflow-companion-<版本>.zip` 是命令行服务，不是桌面安装器；GitHub 的 Source code 也不能直接作为应用安装。其他环境仍可使用基础批注 / 导出，或主动选择文末的高级 CLI 路径。

### 2. 安装打开，自动准备本地连接

- Mac Apple Silicon：打开 DMG，将 ContextFlow 放入「应用程序」，再从该位置打开，不要一直从 DMG 挂载目录运行。当前仅此架构开放下载。
- Mac Intel / Windows：暂未开放安装包下载；保留已安装扩展，基础阅读可继续。高级 CLI 路径是可选替代，不需要为了批注安装 WSL。
- 安装包内置运行环境，不需要最终用户安装 Node.js、Git 或运行 npm。

桌面端启动后自动准备服务与浏览器桥接，并行检查支持的 Agent 入口和 Obsidian 已登记的库，展示候选供确认。没有 Obsidian 也可以稍后选一个普通 Markdown 目录；目前不宣称能自动发现所有笔记软件或任意知识库。发现过程不会全盘扫描、读取笔记正文、替你登录 Agent，或因为发现某个目录就自动授权。

如果存在旧服务占用，先按明确提示处理，不启动第二份、不强杀未知进程。已有配置与阅读数据应保留。自动发现、服务启动、真实模型回答和笔记写入是不同状态，不能由一个“已就绪”推断全部成功。

### 3. 一键连接桌面端

先确认扩展满足[版本与连接要求](#版本与连接要求)，并有「连接桌面端」入口。缺少入口时不要卸载扩展或重新安装桌面端。

1. 核对扩展已更新，理解并按 Chrome 提示确认连接权限，再刷新已打开的文章。
2. 保持桌面端打开，在 Chrome 拼图菜单打开 ContextFlow「扩展程序选项」，进入「连接与设置」。
3. 阅读数据说明，点击「连接桌面端」。
4. 在桌面弹窗核对浏览器申请和安装编号，点击「允许连接」。拒绝不会删除阅读记录，可以稍后再申请。
5. 看到扩展连接成功后，继续配置 AI 或笔记位置。整个过程不需要终端、npm，或手动生成 / 复制配对码。

每个 Chrome 用户配置分别连接，可在桌面端「设置与帮助 → 浏览器授权」独立撤销。桌面连接按 Google Chrome 验证，未对其他 Chromium 浏览器作同等承诺。文末配对码命令只属于高级 CLI 路径，不是桌面安装步骤。

### 4. 按需选择、测试并保存 AI

LLM 配置接口类型、地址、API key 和模型；「获取模型」应显示数量，不支持列举时可手填。点击「测试模型连接」会发送固定短消息，可能产生少量费用，不发送文章和笔记，也不保存配置；确认后还需「保存更改」。

Agent 先选择已发现的本机程序，或填写自定义程序路径，再点击「测试 Agent 连接」，通过后保存更改。测试使用当前草稿，不要求先保存，也不会改动正在使用的配置；仅发送固定短消息，不运行工具或读取笔记。修改程序、路径、版本、凭据或权限档后需重新测试。若当前工具或版本不支持测试 / Safe，按界面说明换用适配工具，不为通过测试提升 Full。解释和速览可使用 Agent，翻译始终需要 LLM。

连接测试通过只验证当时的登录与模型回应，不能证明工具和笔记读取可用。需要参考个人笔记时，单独设置 Agent 的「允许读取的笔记库」，先用不含隐私的测试目录验证；笔记同步目的地不会自动成为读取授权。Safe 的具体边界取决于 Agent 与版本，Full 可能扩大到命令或文件写入等能力，需单独理解并确认。

只同步笔记时可以跳过 AI；只用 AI 时也可以暂不设置笔记。回文章完成一次真实解释或翻译后，桌面端和扩展应展示同份有效配置的使用状态；旧缓存答案不能证明新配置可用。

### 5. 保存并确认笔记目的地，再验证同步

1. 在桌面端「笔记」选择 Markdown、Obsidian 或思源。确认发现的笔记库，或用字段旁的目录选择器指定一个专用测试位置；思源还需配置正在运行的 Kernel、token 与目标笔记本。
2. 点击「保存更改」。选择候选 / 目录只会填入草稿，不自动保存；默认已有路径也不等于你已确认。
3. 核对显示的最终目的地，再点击「确认使用这个位置」。此时是「位置已确认 · 待同步」，没有自动写入。
4. 回文章写一条批注，点击侧栏「同步」，到目标位置核对实际文件或文档。修改批注再同步，应更新同一篇文章，而不是生成重复副本。

**完成标志：** 目标出现带来源与批注的 Markdown（思源为对应文档），桌面端显示「已验证写入」。首次仅执行无变化同步不产生新的写入验证。更换目的地后需重新核对，不能沿用旧位置的成功状态。浏览器内自动保存、复制 / 下载 Markdown 与向笔记软件主动同步是不同操作。

## 版本与连接要求

桌面一键连接需要 Chrome 扩展 **1.1.0 或更高版本**，并允许其连接本机桌面端。可在 `chrome://extensions` 查看当前扩展版本；商店可安装版本以实际商店页面为准。更新后刷新已打开的文章。如没有「连接桌面端」入口，先继续基础阅读，不要通过卸载扩展或清空数据解决。

桌面端、扩展与命令行服务是不同安装包，不要互相替代。客户端下载和系统要求以[官网下载页](https://pengheliu.github.io/ContextFlow/download.html)为准；技术发行与验收记录见[发布准备说明](./RELEASE_READINESS.md)。

## 高级兼容路径：命令行服务

仅适用于已有 CLI 服务、Linux 或明确选择开发者方式的用户，不是普通用户的默认安装步骤。桌面端与 CLI 不要同时启动；桌面端加密保存过配置后，旧 CLI 不能直接读取，回退前先保护数据并参考备份说明。

<details>
<summary>展开命令行安装、配对和配置步骤（需要 Node.js）</summary>

### 1. 下载本地服务，不是再次下载扩展

Chrome 扩展不会自动在电脑上安装配套服务。先安装 [Node.js 22.13 或更高版本](https://nodejs.org/en/download)，安装后重新打开终端。

从[发行页](https://github.com/PengheLiu/ContextFlow/releases)下载与扩展匹配的 `contextflow-companion-<版本>.zip`。将服务包解压到固定位置，里面应有 `package.json`、`server` 和 `tools`。

| 文件 | 用途 |
| --- | --- |
| contextflow-companion-<版本>.zip | 电脑上的本地服务；AI / 笔记同步需要 |
| contextflow-chrome-<版本>.zip | 解压加载的扩展备用包；商店安装者不需要 |
| contextflow-store-site / Source code / .sha256 | 支持网站、源码或校验文件；首次连接不需要 |

### 2. 先进入解压后的服务文件夹

- macOS：打开「终端」，输入 `cd` 后敲一个空格，把服务文件夹拖进终端，按回车。**只打开终端不会自动进入目录。**
- Windows：在资源管理器中打开服务文件夹，在地址栏输入 `cmd` 并回车。下方使用 `&&` 的命令用于命令提示符，不用于旧版 PowerShell。
- Linux：在服务文件夹中右键打开终端，或先使用 `cd`。

不要在主目录（提示符常显示 `~`）或其他项目里直接执行 `npm ci`，它处理的是当前目录的依赖。

### 3. 一次运行安装、配对与启动

命令行连接页可直接复制完整的启动命令。也可使用下面这一整行；命令中的 ID 是正式商店版 ID，解压开发版须使用自身连接页显示的 ID。

~~~bash
node -e "const[v,m]=process.versions.node.split('.').map(Number);if(v<22||(v===22&&m<13)){console.error('请安装 Node.js 22.13 或更高版本，再重新打开终端。');process.exit(1)}let p;try{p=require('./package.json')}catch{}if(p?.name==='contextflow'&&p?.scripts?.server==='node server/index.mjs'&&require('node:fs').existsSync('server/index.mjs')){console.log('目录确认：ContextFlow');process.exit(0)}console.error('目录不对：请先进入解压后的 ContextFlow 服务文件夹，再运行本命令。');process.exit(1)" && npm ci --omit=dev && npm run pair -- aemncphfnlpbhlddifhohpgegejjejfm && npm run server
~~~

命令先检查 Node.js 和目录，再安装依赖、生成本扩展配对码，最后启动服务。某一步失败不会继续；不要只摘取其中的 `npm ci`。安装需要网络，失败时不要用管理员权限强行重试，也不要删除其他项目的文件。

**完成标志：** 首先看到「目录确认：ContextFlow」，随后出现单独一行的 43 位配对码，最后显示监听 `127.0.0.1:7317`。保持终端打开；没有命令提示符返回表示服务正在运行。

### 4. 返回扩展粘贴配对码

1. 在 Chrome 拼图菜单中找到 ContextFlow，打开「扩展程序选项」。
2. 只复制终端里单独一行的 43 位配对码，粘贴到连接页，不是整段输出或模型 API key。
3. 阅读数据使用说明，勾选确认并点击「验证并连接」。

不需要第二个终端；服务仍在第一个终端运行。新版会在失败时保留输入供重试，并在重新打开页面时实际检查连接。配对成功只代表本机服务可用，**不代表模型配置成功**。

如果已经有服务在运行，只需生成配对码：在相同服务目录另开终端运行连接页给出的配对命令。每次新开终端都要再次进入目录。重新生成会让旧码失效，日常启动不要重复配对。

### 5. 先配置笔记位置，完成一次同步

在连接成功后的选项页「笔记同步」中配置。

选择一种后端：

- **本地 Markdown：** 使用默认目录或填写绝对路径与子目录；新版也支持 `~/` 路径。
- **Obsidian：** 选择 Vault。新版无法探测时可以手填 Vault 根目录；当前版如无法探测，可先选择 Markdown，把导出根目录填写为 Vault 的完整路径。无需 Obsidian REST 插件。
- **思源：** 启动思源，填写自己的 Kernel 地址和 API token，保存后刷新笔记本，明确选择目标笔记本与目录。不使用任何维护者的笔记本 ID。

保存配置后，在文章里写一条测试批注，点击侧栏「同步」。先用空白测试目录。

**完成标志：** 目标位置出现当前文章的 Markdown（思源为目标文档），里面包含原文与批注。再次同步更新同一篇笔记，而不是每次生成副本。仅同步笔记无需配置 AI；浏览器自动保存不等于自动写入笔记软件。

### 6. 按需配置和测试 AI

模型连接供翻译、LLM 解释与速览共用，需要你自己的模型账号及额度，配对码不能替代 API key。

解释和文章速览可改用本地 Agent；翻译始终使用 LLM，不能只配置 Agent。回答方式旁的问号可以展开能力与授权范围说明。

1. 选择接口类型，填写服务提供方的 Base URL、API key 和模型名称。
2. 可点击「获取模型」，或直接手填服务提供方给出的模型名。不是每个兼容服务都提供模型列表。
3. 点击「测试模型连接」仅验证当前草稿，不保存配置；成功后还需点击「保存更改」。测试发送固定短消息，可能产生少量费用，不发送文章或笔记。
4. 模型测试成功后再打开文章使用解释、翻译与速览。AI 处理可能把正文、问题及授权笔记发送给所选服务。

个人笔记与本地 agent 是进阶功能：自行安装并登录 CLI，再检测并选择 agent，授权要读取的目录。检测到可执行文件不等于账号已登录，也不等于模型服务可用。先保留默认受限权限；不支持的 CLI 或完整权限另行评估，不建议首次安装直接开启。

## 日常运行与升级

### 桌面端

关闭窗口不停止后台连接。Mac 保留 Dock 作为菜单栏之外的找回入口；点击菜单栏图标只展开状态菜单，选择「打开 ContextFlow」或点击 Dock 可回到原窗口。菜单栏拥挤、刘海或第三方管理工具可能隐藏图标，不能只凭图标尺寸断定它可见。Windows 在托盘不可用时保留最小化窗口。选择「退出 ContextFlow」才会停止服务，有任务时先确认。

再次打开应保留配对，不需重装。登录启动由你主动开启；它不等于扩展已经连接或模型已验证。不要同时恢复旧 CLI 自启。

扩展和桌面端分别更新。桌面端采用官网下载后手动覆盖安装，不承诺应用内自动下载 / 安装：先保存工作并备份，等待任务结束，正常退出旧版，再从官网下载实际开放的对应系统 / 架构版本，核对其签名说明与校验文件，覆盖应用而不卸载或删除数据。当前公开的是未签名、未公证的 Mac Apple Silicon 包，不要将它理解为已完成 Apple 安全验证。重新打开后核对版本、连接和目的地；已保存的桌面连接无需日常重配。

本机恢复点只保护当前电脑原账号的服务数据库、附件、配置与密钥；不包含浏览器尚未同步记录、外部笔记文件或浏览器授权。使用阅读库的完整备份保护浏览器记录。回退旧 CLI 需要测试前备份，不能直接重启旧 LaunchAgent。

### 命令行服务（高级兼容）

遇到问题时，可在扩展选项页打开「帮助与诊断 → 运行诊断」。先预览报告，需要反馈时再复制；它只检查健康状态和存储计数，不调用 AI，不包含网址、正文、密钥、配对码或完整日志。不要为了排障卸载扩展或删除配置。

关闭服务终端会停止 AI / 同步，但批注与配对信息不会因此清除。下次进入同一个服务文件夹执行 `npm run server`，无需重新安装或配对。新版连接页提供带目录检查的重新启动命令。

macOS 希望登录后自动启动时，先 Ctrl+C 停止前台服务，再在同一固定目录执行 `npm run service`。Windows / Linux 目前保持前台终端运行，没有经过实机验证的自动常驻安装器。不要同时启动前台与常驻服务。

更新模型不需要重装扩展。移动服务目录后，macOS 常驻服务需重新安装；扩展和本地服务分别升级。新版本需先发布配套服务，再提交商店扩展，避免用户点到不存在的下载。

定期导出或同步。卸载扩展会清除浏览器侧记录，但不会删除已导出的文件或已同步笔记。旧开发版升级前先导出或同步。

## 遇到问题

| 看到的情况 | 接下来怎么做 |
| --- | --- |
| 安装后没有工具条 | 刷新普通文章，确认扩展启用并允许在当前网站运行 |
| Chrome 商店页、内部页面或 PDF 不能批注 | 换到普通正文网页；arXiv 使用 abs/html 页面 |
| 练习文章只是普通网页 | 它不是免安装模拟，需要启用扩展 |
| `npm` 不存在 | 安装 Node.js 后重新打开终端；用 `node -v` 检查版本 |
| 提示「目录不对」、找不到 package.json 或出现陌生包名 / E404 | 返回服务文件夹步骤，核对当前项目；不要直接换源或删除文件 |
| 安装失败、超时或网络不可达 | 保留完整错误，检查网络 / 代理配置；不要公开上传 npm 配置或凭证 |
| 端口被占用 | 桌面端先到「设置与帮助」核对旧服务；手动 CLI 在原终端停止，仅在明确归属且空闲时接管已识别服务，不盲目结束其他应用 |
| 桌面端未连接 | 先打开已安装的应用，检查浏览器是否有待批准连接；不要去终端再启动第二份服务 |
| 找不到「连接桌面端」入口 | 核对扩展为 1.1.0 或更高版本，商店可安装版本以实际页面为准；先继续基础阅读，不卸载扩展、不清空数据 |
| Mac 无法打开下载的应用 | 先核对官方来源和架构，按 Apple 安全说明区分提示；不关闭系统防护，遇到损坏或恶意软件提示停止并反馈 |
| 更新后扩展被 Chrome 暂停 | 查看扩展管理页的新权限提示，理解后决定是否启用；不要卸载来“修复” |
| 桌面端显示发现 Agent / 笔记 | 这是候选，不等于登录、授权、回答或同步成功；分别确认并完成真实使用 |
| CLI 服务未连接 | 保持服务终端打开，先重新启动服务，再检查连接，无需立即重配 |
| 高级 CLI 配对码无效 | 仅 CLI 用户在对应服务目录运行配对命令，复制 43 位代码；桌面 1.1 一键流程不要求手动生成或粘贴配对码 |
| 服务已连上但 AI 失败 | 检查接口类型、地址、模型、密钥、额度，以及 agent 登录状态 |
| 测试提示「无此路由 POST /llm/test」或「本地服务版本过旧」 | 扩展与本地端分别更新。桌面用户先核对桌面版本并正常退出 / 重开；旧 CLI 用户停止旧进程、换用匹配 companion 后重启，macOS 常驻 CLI 可在原服务目录执行 `npm run service -- restart`。不要对桌面加密配置直接启动旧 CLI |
| 点获取模型后没有看到结果 | 获取成功会显示数量；没有列表时仍可手填。获取成功不代表推理调用成功，需另点「测试模型连接」，确认后再保存 |
| 笔记未出现 | 保存目的地后明确确认，再回文章点「同步」；检查真正的目标目录、笔记本与权限，单次模型测试不验证同步 |
| 关闭窗口后找不到应用 | Mac 从 Dock 或「应用程序」打开，或从菜单栏「打开 ContextFlow」找回；Windows 检查托盘 / 最小化窗口。不要重复安装或再开 CLI 服务 |
| 原文高亮不见但侧栏有记录 | 网页可能改版，保留记录并导出，不要清空缓存 |

仍无法解决时，[反馈问题](https://github.com/PengheLiu/ContextFlow/issues)并附扩展、桌面端（或 CLI 服务）与浏览器版本、操作步骤及脱敏截图；只有命令行安装问题才需补充 Node / npm 版本。不要上传配对码、API key、私人笔记、完整配置或 npm 凭证。
