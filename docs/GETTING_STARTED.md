# 从第一条批注开始

[返回首页](../README.md) · [练习文章](https://pengheliu.github.io/ContextFlow/demo.html) · [下载 v0.3.1](https://github.com/PengheLiu/ContextFlow/releases/tag/v0.3.1)

你不必一次设置好全部功能。先完成「选中原文 → 写批注 → 下载 Markdown」，需要 AI 或自动同步时，再开启本地服务。

## 安装扩展

Chrome 商店版 v0.3.1 正在等待审核；目前可使用解压加载的试用版。这一步不需要 Git、Node.js 或终端。

1. 打开上方下载页，展开 Assets，下载 **contextflow-chrome-0.3.1.zip**。
2. 解压到固定文件夹，不要删除或移动这个文件夹。
3. 在 Chrome 地址栏输入 `chrome://extensions`，打开右上角「开发者模式」。
4. 点击「加载已解压的扩展程序」，选择包含 `manifest.json` 的文件夹。成功时，扩展列表里会出现 ContextFlow。
5. 打开普通文章网页并刷新。安装时已打开的文章需要刷新后才能使用。

下载文件别选错：

| 文件 | 用途 |
| --- | --- |
| contextflow-chrome-0.3.1.zip | 浏览器扩展；先下载这个 |
| contextflow-companion-0.3.1.zip | 可选本地服务；需要 AI 或自动同步时再下载 |
| contextflow-store-site / Source code / .sha256 | 网站、开发源码或校验文件；首次使用不需要 |

可以把扩展固定在工具栏：点 Chrome 右上角拼图图标，再点 ContextFlow 旁的图钉。商店版获批后，普通用户会直接通过商店安装，不再需要解压加载。

## 完成第一条批注

1. 打开[练习文章](https://pengheliu.github.io/ContextFlow/demo.html)，选中第一段的一句话。
2. 选区旁出现工具条后，点「批注」，直接输入一句自己的理解；也可复制截图后粘贴。
3. 打开页面右侧的把手，在「批注」页确认能看到原文和自己的想法。
4. 刷新文章，确认批注和高亮恢复。再点侧栏底部「下载」，用任意文本编辑器或 Obsidian 打开得到的 `.md` 文件。

**完成标志：** 文章刷新后记录还在，下载的文件里同时有原文、自己的批注和来源链接。

v0.3.1 的安装欢迎页会先展示连接步骤；只想批注时可关闭它，直接到文章选中文字。源码中新的欢迎页和未配对图标行为会在后续版本提供。

如果只想保留阅读记录，到这里就可以开始日常使用。导出文件可以手动放进笔记软件；自动写入才需要下面的服务。

## 开启 AI 和笔记同步

### 1. 准备本地服务

安装 [Node.js 22.5 或更高版本](https://nodejs.org/en/download)，再下载并解压 **contextflow-companion-0.3.1.zip**。放到以后不会随意移动的文件夹。

在解压后有 `package.json` 的文件夹打开终端：

- macOS：打开「终端」，输入 `cd `（末尾一个空格），把服务文件夹拖进终端，然后按回车。
- Windows：用文件资源管理器打开服务文件夹，在地址栏输入 `powershell` 并回车。
- Linux：在服务文件夹选择「在终端中打开」，或使用 `cd` 进入该目录。

先运行一次安装：

```bash
npm ci --omit=dev
```

安装结束后启动：

```bash
npm run server
```

**完成标志：** 终端显示服务监听 `127.0.0.1:7317`。保持终端打开；没有命令提示符返回，是服务正在运行，不是卡住了。此地址只在本机使用，不需要开放公网端口。

### 2. 配对扩展

1. 在 Chrome 拼图菜单中找到 ContextFlow，通过菜单里的「选项」或扩展详情里的「扩展程序选项」打开连接页。
2. 复制页面显示的配对命令。请使用自己安装的扩展显示的命令，商店版与解压版的 ID 可能不同。
3. 在**同一个服务文件夹另开一个终端**，粘贴命令并执行。不要在正在运行服务的终端中输入。
4. 复制生成的配对码，粘贴回扩展页，确认数据使用说明并点击「验证并连接」。

**完成标志：** 页面显示「连接成功」，输入框里的配对码被清空。它已保存在扩展中，不需要每次使用都重新配对。

配对码只授权本机连接，不是模型 API key。不要把它放进反馈、截图或聊天。重新生成会让旧码失效。

### 3. 先设置一个笔记保存位置

刷新文章，展开侧栏并进入「配置」，找到「笔记后端」：

- **本地 Markdown：** 不使用特定笔记软件也可以。选择保存目录，或先使用配置页显示的默认位置。
- **Obsidian：** 选择已有 Vault 和阅读记录目录；不需要额外安装 Obsidian 插件。
- **思源：** 需要启动思源并配置自己的 Kernel API 与目标位置，建议熟悉后再用。

保存配置，回到阅读记录点「同步」。第一次建议使用空白测试目录。

**完成标志：** 在目标目录找到当前文章的 Markdown（思源则查看目标文档），原文与自己的批注在同一处。再次同步会更新记录，而不是为每次点击重复生成文章。

只用笔记同步，不必填写 AI 配置。以后希望自动保存时，再考虑常驻服务。

### 4. 需要时再设置 AI

在侧栏「配置」里填写模型服务地址、自己的 API key 和模型；可以通过「获取模型」选择可用模型。配置方式取决于你使用的服务，扩展不提供内置账号或免费额度。

选择一小段非敏感原文，点击「解释」，输入一个具体问题再提交。读完已有答案后，顶部可以直接重新解释。

**完成标志：** 面板显示正常回答，而不是仅显示“已连接”。配对成功只代表本地服务可用，不代表模型配置已经完成。打开长文章阅读面板可能触发 AI 速览并消耗模型额度。

个人笔记和本地 agent 属于进阶功能：先安装并登录相应 agent，在配置页「检测」，再明确选择允许读取的笔记目录。建议先保持默认受限配置。

## 日常运行与升级

使用 AI 或自动同步时，需要本地服务正在运行。临时停止可在服务终端按 `Ctrl+C`；下次在服务文件夹执行 `npm run server` 即可，通常无需重新安装或配对。

macOS 用户可先停止前台服务，再运行 `npm run service` 安装登录后自动启动的常驻服务。Windows / Linux 暂使用前台运行方式；尚无经过验证的自动安装器。

更新模型配置不需要重新安装扩展。升级本地服务请按发行说明操作；移动服务文件夹后，macOS 常驻服务需重新安装。扩展和配套服务分别更新。

扩展私有记录不是云端备份。定期下载或同步；卸载扩展前先导出。从旧开发版迁移时，也请先同步或导出旧缓存。

## 遇到问题

| 看到的情况 | 接下来怎么做 |
| --- | --- |
| 安装后没有工具条 | 先刷新文章；确认扩展启用，浏览器已允许在当前网站运行 |
| Chrome 商店页或 PDF 不能批注 | 换到普通正文网页；arXiv 使用 abs/html 页面 |
| 练习文章只是普通网页 | 它不是免安装在线模拟；需要先安装并启用扩展 |
| 下载了 ZIP 但 Chrome 无法加载 | 先解压，选包含 manifest.json 的文件夹 |
| `npm` 不存在或不是内部命令 | 安装 Node.js，再重新打开终端 |
| 找不到 package.json | 终端当前目录不对，进入解压的 companion 文件夹 |
| 配对后连接不上 | 保持服务终端运行；下一版欢迎页可点击「检查本地服务连接」 |
| 配对码失效 | 从扩展自己的连接页重新复制命令，生成新码后再验证 |
| 服务已连上但 AI 报错 | 检查模型配置、额度，以及本地 agent 是否登录；批注仍可使用 |
| 提示端口已占用 | 可能已有服务在运行；macOS 用 `npm run service -- status` 查看，避免重复启动 |
| 记录在侧栏里，原文高亮不见了 | 网页可能已改版；记录仍可导出，可从侧栏重新定位 |

仍无法解决时，前往[问题反馈](https://github.com/PengheLiu/ContextFlow/issues)，描述操作步骤、浏览器和扩展版本。截图前隐藏配对码、API key、私人笔记和路径。
