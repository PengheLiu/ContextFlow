# 从第一条批注开始

[产品官网](https://pengheliu.github.io/ContextFlow/) · [GitHub 首页](../README.md) · [Chrome 商店安装](https://chromewebstore.google.com/detail/contextflow/aemncphfnlpbhlddifhohpgegejjejfm) · [练习文章](https://pengheliu.github.io/ContextFlow/demo.html)

先完成「选中原文 → 写批注 → 下载 Markdown」，需要 AI 或笔记同步时再连接本地服务。

> 截至 2026-10-19，商店版本是 v0.3.1。v0.3.2 新连接引导与同页配置已提交 Google 审核，通过后自动发布；[配套服务 v0.3.2](https://github.com/PengheLiu/ContextFlow/releases/tag/v0.3.2)已公开。下面保留 v0.3.1 可立即执行的兼容步骤；以扩展详情中显示的实际版本为准，GitHub 发行不代表商店已经更新。

## 安装扩展

1. 在商店点击「添加至 Chrome」，确认安装，无需开启开发者模式。
2. 点击 Chrome 右上角拼图图标，把 ContextFlow 固定到工具栏。
3. 刷新一篇普通文章。安装前已经打开的网页必须刷新。

高亮、批注、图片补充和 Markdown 导出不需要账号、Node.js、API key 或本地服务。v0.3.1 首次打开的是连接页，只想批注时可关闭该页，直接到文章选中文字。

### 手动安装备用路径

只有无法使用商店或需要开发测试时，才从[发行页](https://github.com/PengheLiu/ContextFlow/releases/latest)下载 `contextflow-chrome-<版本>.zip`，解压后在 `chrome://extensions` 开启开发者模式，加载包含 `manifest.json` 的文件夹。不要与商店版同时启用，避免重复面板；卸载旧版前先导出其独立的阅读数据。

## 完成第一条批注

1. 打开[练习文章](https://pengheliu.github.io/ContextFlow/demo.html)，选中第一段的一句话。
2. 点击选区工具条「批注」，在原文旁写一句自己的理解，也可以粘贴图片。
3. 展开页面右侧把手，确认批注与原文出现在侧栏。
4. 刷新页面检查记录恢复；点击侧栏底部「下载」，用文本编辑器或 Obsidian 打开 Markdown。

**完成标志：** 刷新后记录仍在，Markdown 同时包含原文、自己的想法和来源链接。原文网页改版可能影响标记定位，但已有记录仍可导出。

## 开启 AI 和笔记同步

### 1. 下载本地服务，不是再次下载扩展

Chrome 扩展不会自动在电脑上安装配套服务。先安装 [Node.js 22.13 或更高版本](https://nodejs.org/en/download)，安装后重新打开终端。

当前 v0.3.1 用户可[下载 companion 服务包 v0.3.1](https://github.com/PengheLiu/ContextFlow/releases/download/v0.3.1/contextflow-companion-0.3.1.zip)。已安装 v0.3.2 的用户可在连接页下载，或[直接下载 companion v0.3.2](https://github.com/PengheLiu/ContextFlow/releases/download/v0.3.2/contextflow-companion-0.3.2.zip)。按扩展实际版本选择，将服务包解压到固定位置，里面应有 `package.json`、`server` 和 `tools`。

| 文件 | 用途 |
| --- | --- |
| contextflow-companion-<版本>.zip | 电脑上的本地服务；AI / 笔记同步需要 |
| contextflow-chrome-<版本>.zip | 解压加载的扩展备用包；商店安装者不需要 |
| contextflow-store-site / Source code / .sha256 | 支持网站、源码或校验文件；首次连接不需要 |

### 2. 先进入解压后的服务文件夹

- macOS：打开「终端」，输入 `cd` 后敲一个空格，把服务文件夹拖进终端，按回车。**只打开终端不会自动进入目录。**
- Windows：在资源管理器中打开服务文件夹，在地址栏输入 `cmd` 并回车。下方使用 `&&` 的命令用于命令提示符，不用于旧版 PowerShell。
- Linux：在服务文件夹中右键打开终端，或先使用 `cd`。

不要在主目录（提示符常显示 `~`）或其他项目里直接执行 `npm ci`，它处理的是当前目录的依赖。

### 3. 一次运行安装、配对与启动

新版连接页可直接复制完整的启动命令。当前 v0.3.1 商店用户也可使用下面这一整行；命令中的 ID 是正式商店版 ID，解压开发版须使用自身连接页显示的 ID。

~~~bash
node -e "const[v,m]=process.versions.node.split('.').map(Number);if(v<22||(v===22&&m<13)){console.error('请安装 Node.js 22.13 或更高版本，再重新打开终端。');process.exit(1)}let p;try{p=require('./package.json')}catch{}if(p?.name==='contextflow'&&p?.scripts?.server==='node server/index.mjs'&&require('node:fs').existsSync('server/index.mjs')){console.log('目录确认：ContextFlow');process.exit(0)}console.error('目录不对：请先进入解压后的 ContextFlow 服务文件夹，再运行本命令。');process.exit(1)" && npm ci --omit=dev && npm run pair -- aemncphfnlpbhlddifhohpgegejjejfm && npm run server
~~~

命令先检查 Node.js 和目录，再安装依赖、生成本扩展配对码，最后启动服务。某一步失败不会继续；不要只摘取其中的 `npm ci`。安装需要网络，失败时不要用管理员权限强行重试，也不要删除其他项目的文件。

**完成标志：** 首先看到「目录确认：ContextFlow」，随后出现单独一行的 43 位配对码，最后显示监听 `127.0.0.1:7317`。保持终端打开；没有命令提示符返回表示服务正在运行。

### 4. 返回扩展粘贴配对码

1. 在 Chrome 拼图菜单中找到 ContextFlow，打开「扩展程序选项」。
2. 只复制终端里单独一行的 43 位配对码，粘贴到连接页，不是整段输出或模型 API key。
3. 阅读数据使用说明，勾选确认并点击「验证并连接」。

不需要第二个终端；服务仍在第一个终端运行。新版会在失败时保留输入供重试，并在重新打开页面时实际检查连接。配对成功只代表本机服务可用，**不代表模型配置成功**。

如果已经有服务在运行，只需生成配对码：在相同服务目录另开终端运行连接页给出的配对命令。每次新开终端都要再次进入目录。重新生成会让旧码失效，日常启动不要重复配对。

### 5. 先配置笔记位置，完成一次同步

- v0.3.2 发布后：可直接在连接成功后的当前页面「归档」中配置。
- 当前 v0.3.1：返回文章、刷新，展开侧栏，点击「配置」，找到「归档」。

选择一种后端：

- **本地 Markdown：** 使用默认目录或填写绝对路径与子目录；新版也支持 `~/` 路径。
- **Obsidian：** 选择 Vault。新版无法探测时可以手填 Vault 根目录；当前版如无法探测，可先选择 Markdown，把导出根目录填写为 Vault 的完整路径。无需 Obsidian REST 插件。
- **思源：** 启动思源，填写自己的 Kernel 地址和 API token，保存后刷新笔记本，明确选择目标笔记本与目录。不使用任何维护者的笔记本 ID。

保存配置后，在文章里写一条测试批注，点击侧栏「同步」。先用空白测试目录。

**完成标志：** 目标位置出现当前文章的 Markdown（思源为目标文档），里面包含原文与批注。再次同步更新同一篇笔记，而不是每次生成副本。仅同步笔记无需配置 AI；浏览器自动保存不等于自动写入笔记软件。

### 6. 按需配置和测试 AI

模型连接供翻译、LLM 解释与速览共用，需要你自己的模型账号及额度，配对码不能替代 API key。

1. 选择接口类型，填写服务提供方的 Base URL、API key 和模型名称。
2. 可点击「获取模型」，或直接手填服务提供方给出的模型名。不是每个兼容服务都提供模型列表。
3. 新版提供「保存并测试模型连接」，会发送固定短消息并可能产生少量费用，不会发送文章或笔记。当前 v0.3.1 请展开「连接与上下文」填写地址和密钥，保存后用一小段公开原文点击「解释」验证。
4. 模型测试成功后再打开文章使用解释、翻译与速览。AI 处理可能把正文、问题及授权笔记发送给所选服务。

个人笔记与本地 agent 是进阶功能：自行安装并登录 CLI，再检测并选择 agent，授权要读取的目录。检测到可执行文件不等于账号已登录，也不等于模型服务可用。先保留默认受限权限；不支持的 CLI 或完整权限另行评估，不建议首次安装直接开启。

## 日常运行与升级

关闭服务终端会停止 AI / 同步，但批注与配对信息不会因此清除。下次进入同一个服务文件夹执行 `npm run server`，无需重新安装或配对。新版连接页提供带目录检查的重新启动命令。

macOS 希望登录后自动启动时，先 Ctrl+C 停止前台服务，再在同一固定目录执行 `npm run service`。Windows / Linux 目前保持前台终端运行，没有经过实机验证的自动常驻安装器。不要同时启动前台与常驻服务。

更新模型不需要重装扩展。移动服务目录后，macOS 常驻服务需重新安装；扩展和本地服务分别升级。新版本需先发布配套服务，再提交商店扩展，避免用户点到不存在的下载。

定期导出或同步。卸载扩展会清除浏览器侧记录，但不会删除已导出的文件或已同步笔记。旧开发版升级前先导出或同步。

## 遇到问题

| 看到的情况 | 接下来怎么做 |
| --- | --- |
| 安装后没有工具条 | 刷新普通文章，确认扩展启用并允许在当前网站运行 |
| Chrome 商店页、内部页面或 PDF 不能批注 | 换到普通正文网页；arXiv 使用 abs/html 页面 |
| 练习文章只是普通网页 | 它不是免安装模拟，需要启用扩展 |
| `npm` 不存在 | 安装 Node.js 后重新打开终端；用 `node -v` 检查版本 |
| 提示「目录不对」、找不到 package.json 或出现陌生包名 / E404 | 返回服务文件夹步骤，核对当前项目；不要直接换源或删除文件 |
| 安装失败、超时或网络不可达 | 保留完整错误，检查网络 / 代理配置；不要公开上传 npm 配置或凭证 |
| 端口被占用 | 可能已有 ContextFlow 服务，先回扩展验证连接；不要盲目结束其他应用 |
| 服务未连接 | 保持服务终端打开，先重新启动服务，再检查连接，无需立即重配 |
| 配对码无效 | 使用当前扩展的命令重新生成，只粘贴 43 位代码 |
| 服务已连上但 AI 失败 | 检查接口类型、地址、模型、密钥、额度，以及 agent 登录状态 |
| 笔记未出现 | 保存归档配置后回文章点「同步」，检查实际目标目录与权限 |
| 原文高亮不见但侧栏有记录 | 网页可能改版，保留记录并导出，不要清空缓存 |

仍无法解决时，[反馈问题](https://github.com/PengheLiu/ContextFlow/issues)并附扩展、服务、Node 与浏览器版本、操作步骤及脱敏截图。不要上传配对码、API key、私人笔记、完整配置或 npm 凭证。
